# ICA04 Reflection


## 1. Local and Remote Repositories



The local TaskTrack repository is stored on my computer, where I can edit files, run the program, and create Git commits. The remote repository is hosted on GitHub, where the project and its commit history can be stored and accessed online. Git allows me to synchronize changes between my local repository and the remote repository.



## 2. Connecting and Pushing



Adding `origin` only connects my local repository to the GitHub repository by saving its remote URL. It does not automatically upload my project files or commits to GitHub. I needed to use `git push` to send my local commits to the remote repository.



## 3. Cloning



Cloning a repository creates a local copy of the project along with its Git history and connection to the remote repository. Downloading the files as a ZIP archive only provides a copy of the files and does not set up the same Git repository connection and commit history. Cloning is useful when I want to continue working on a project using Git.



## 4. Fetching and Pulling



The `git fetch` command updates my local information about commits and changes available in the remote repository without changing my working files. The `git pull` command fetches the remote changes and integrates them into my current local branch. This allows me to update my local repository with changes made remotely.



## 5. Focused Commits



Making separate commits for the Python feature, sample task data, and README documentation helps keep the project history organized and easier to understand. Each commit describes a specific change, making it easier to review the work and identify problems if necessary. Focused commits also show the progress of the project more clearly.
